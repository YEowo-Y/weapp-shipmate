# 任务主页改造计划

日期：2026-10-20

## 目标与边界

用户已同意推进上一轮信息架构建议。统一浏览器工作台与正式桌面端的任务入口，突出项目预检、上线清单以及已有会话；移除主页的八阶段示例进度、无实际执行作用的检查开关和常驻空审阅区。保留持久化、模型连接、停止、错误恢复及现有审阅身份校验。

本轮不增加依赖，不迁移存储，不实现虚构的项目历史、完成百分比或自动修复。浏览器不具备原生目录检查能力，必须说明使用桌面端；本机清单生成无需模型。项目报告仍由用户明确加入会话，不自动发送给模型。

## 修改顺序

1. 记录现有工作台截图，并运行会话、工具及响应式相关基线测试。
2. 在共享会话组件增加可选侧栏布局：新任务、历史搜索、会话列表、当前会话重命名，继续使用原有会话状态和持久化。
3. 正式桌面端使用相同导航组织。主页展示两个真实任务入口；保留已有目录和主体配置、报告生成与复制流程，通过明确 API 按需打开项目工具。
4. 浏览器工作台删除示例阶段和假开关，首次使用为空主页；保留已有用户会话。清单入口复用既有参数对话框和流式工具执行；预检入口解释桌面端边界。审阅仅由当前会话的有效记录打开，可关闭并恢复焦点。
5. 独立审查与视觉验收，修复发现的问题后完成构建、测试及 Windows 原生回归。

## 分工

- 共享会话侧栏：session-workspace.js、session-workspace.css、对应测试。
- 正式桌面：desktop/index.html、desktop/src 中主页/会话/工具面板及对应测试。
- 浏览器工作台：main-four-region.html、main.js、main.css、ui.js、responsive.js 与相关测试。
- 主执行者负责集成、浏览器/原生验收、报告和视觉状态记录。

## 验收

- 首次打开没有预置成功报告、进度或待批准示例，已有历史和草稿仍可恢复。
- 新建、搜索、最近会话切换、重命名复用同一状态，流式中切换正确停止并保存。
- 桌面预检使用真实目录和主体，清单无需模型；错误可重试，旧结果清楚标识。
- 浏览器首页可启动真实本机清单；项目预检不冒充可在浏览器读取目录。
- 结果面板默认关闭，无关/过期事件不能打开，关闭恢复触发器焦点；窄屏无横向溢出。
- 对话区保持有界阅读宽度，导航、任务入口、设置与报告有明确层级；图标复用既有资源。
