# 会话历史持久化与恢复：官方证据

核对日期：2026-10-18。类型：有界最佳实践调研。复用 `session-navigation-agent-sources.md` 和 `session-experience-sources.md`，本轮只打开 2 个产品官方页、2 个 MDN 页。没有登录、运行上游客户端、修改产品代码或新增依赖。

## 结论

区分“本浏览器保存的历史”“服务端持有的会话”“云备份/同步”和“运行恢复”。加载旧消息不证明任务仍在运行；没有服务端续跑凭据与状态核对时，刷新后的未完成输出应明确显示中断并保留已有文本。搜索应覆盖实际保留且成功载入的会话，读取失败不能伪装成没有历史。这些是依据下述事实提出的产品建议，不是对本仓库现状的验证。

## 产品文档事实

### OpenClaw

来源：[Session management](https://docs.openclaw.ai/concepts/session)。滚动官方文档，无固定发行版本。

- Gateway 拥有会话状态，UI 向它查询；当前文档描述会话行和正文使用每 Agent 的 SQLite。它不等同浏览器本地存储方案。
- 重启打断的回复，在写入器可用时保留已输出文本并标为中断。自动恢复受条件限制；恢复耗尽仍保留任务和历史，提供 Resume；特定运行时则提供在新会话恢复。恢复重新检查权限，未知外部副作用需检查后再重复。
- 检测到需要迁移的旧存储时，不以空历史悄悄启动，而是显示修复指引。会话名称更新保留已有摘要；新消息、正文替换及冷存储恢复会刷新摘要。
- 文档区分会话历史与可选的跨会话记忆检索；不能把历史列表搜索说成模型的长期记忆。

版本注意：搜索引擎还返回较旧的 `/sessions` 摘要，其恢复描述只强调新会话；本轮以上述实际打开的 `/concepts/session` 正文为准，且不声称当前安装版已经具备所有滚动文档功能。

### Cherry Studio

来源：[Data Settings](https://cherryai.com/docs/en/pre-basic/data-settings/)。桌面官方滚动文档。

- 数据页将备份、恢复与跨设备传递集中管理；本地备份选目录，WebDAV 的跨设备例子是 A 备份、B 恢复，另支持 S3。不能由此推断无冲突的实时云同步。
- 完整备份包括会话、话题、设置、知识库和文件；轻量备份省略图片等数据文件。产品备份还可能含 API 密钥，这不是本项目应复制的历史序列化范围。
- 清除应用缓存不删除聊天和设置；重置数据则删除这些内容。两种入口必须明确区分。
- 本页没有承诺中断运行自动续跑，也没有显示保留历史搜索的结果界面；本轮不将此补成“官方行为”。

## 四项可落地建议（项目推导）

1. **把保存边界写清楚。** 若采用浏览器持久化，说明“历史保存在此浏览器，未同步到云端”；这只描述历史保存位置，不能误导用户以为模型请求不发送给服务商。保存对象只包含既有会话契约允许的消息、标题、时间、草稿和必要选择状态，不混入密钥、运行控制对象或未经筛选的工具原始数据。
2. **从保留历史重建导航和搜索。** 成功读取后恢复稳定会话 ID 与当前选择，复用现有搜索；保留手动名称、顺序和消息摘要。读取异常时显示错误，避免用空数组覆盖原存储。加载中、读取失败、确实无历史和查询无匹配是不同状态；暂不因 UI 列表长度擅自删除旧会话。
3. **恢复内容与恢复执行分开。** 新页面实例没有仍有效的运行连接时，将持久化的 generating/tool-running 状态收敛为中断，保留部分文字；不恢复 shimmer、伪造工具成功或自动重发。提供已有的重新生成/继续输入路径，并按其真实语义命名。可用文案：“上次回复已中断，已保留生成的内容。”只有获得可验证服务端运行状态后才能显示继续运行。
4. **失败可见且不破坏当前工作。** 写入失败仍保留内存消息及输入，可用文案：“历史未能保存，当前内容仍可查看；刷新或关闭可能丢失。”读取失败可显示：“暂时无法读取历史，请重试；已保存的数据未被清除。”后一句仅在实现确实未清除时使用。通过合并写入减轻流式负担，终态及时保存，hidden 仅作为补充刷新机会；不要为自动保存展示持续加载圈。

## 建议验收证据（尚未执行）

- 同一 origin 刷新后，手动名称、已完成消息、草稿、选中会话与搜索结果保留；空会话不生成伪历史。
- 生成中刷新：已保存的部分输出可读、显示中断、不会重复请求或出现永久生成态；仅切浏览器标签不应触发这一恢复转换。
- 模拟读取异常、无效版本/损坏内容及写入拒绝：提示与结果对应，不覆盖旧数据，不丢失当前输入；错误恢复后才显示已保存。
- 以合理的长历史检查输入与流式更新不被同步整库写入拖慢。多标签可能并发改同一 origin；合并或冲突策略须由实现方明确并验证，MDN 的 storage 通知本身不解决冲突。

本轮只交付证据与验收建议，不声称产品已具备持久化、云同步、服务端恢复或数据迁移能力。
