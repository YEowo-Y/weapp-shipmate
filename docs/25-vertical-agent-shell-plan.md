# 25 · 垂直 agent 外壳与上线方案（评审与计划）

初版 2026-11-12，2026-11-13 修订。本文合并四轮评审结论：现状评审与竞品对标、产品定位与功能建议、官方工具接入与外壳设计、云与后端接入及交接准备。**只是方案，没有改动任何产品代码，也没有改动治理文件**；外壳预览在 `docs/previews/`，是设计稿，不是实现。

本文只讲「是什么、为什么」。按它动手的工单、步骤和完成判据在 `docs/26-implementation-handoff.md`，文中的 T01–T08 即那里的工单编号。

每条结论后标注证据强度：

| 标记 | 含义 |
|---|---|
| 实跑 | 本轮在本机执行命令或读源码确认 |
| 审查 | 子代理通读代码后的结论，主代理未逐项复核 |
| 调研 | 来自官方文档或公开资料的检索，未在本机验证 |
| 推断 | 由已知事实推出，未复现 |
| 未核实 | 没有找到可靠依据，决策前需要补查 |

## 0. 结论

1. **定位**：以 Codex / Claude 桌面端的外壳和交互为基准，在其上做「微信小程序上线」这一个垂直方向的差异化。对话是主角，上线进度、规则依据、改动审查、开发者工具是右侧面板里的四个标签。
2. **不可替代的部分**是带官方原文和核验日期的规则库、上线阶段模型、拒因反查，以及「不代办、不收集密钥、源码默认留在本机」的边界。通用 agent 能力不是差异点，只做到够用。
3. **agent 能读取并修改源码，按分档做**（已裁决）：默认仍是现在的摘要模式；用户对某个项目显式开启后进入 agent 模式，开启时说明文件内容会发给其自选的模型服务商；私有文件排除清单由本机强制。任何档位都不提审、不发布（§5）。
4. **官方工具分三层接入**：先连用户本机已登录的开发者工具 CLI；开发者工具 MCP 可用后接入；`miniprogram-ci` 只作可选组件。**可以上传体验版**（已裁决）：默认关闭、设置里显式打开、每次上传弹确认、MCP 适配层不暴露（§4.3）。
5. **云与后端能接一部分**：无凭据的域名与证书就绪检查、CloudBase MCP 只读白名单、开发者工具自带的云开发只读命令。要密钥或会写入的（微信云托管 CLI、腾讯云其他 MCP、服务器直连）不接（§4.4）。
6. **引擎不换**：继续扩展现有 AI SDK 循环，不嵌入 Codex app-server 或 Claude Agent SDK。规则内核以 MCP server、plugin、skill 的形式进入两家生态。
7. **首发只做 Windows x64**；macOS 桌面版移出计划，Mac 用户用 npm 包和插件。仓库暂不公开，因此签名和 npm provenance 暂不可用，桌面版先未签名并附 SHA256。
8. **最急的事与新外壳无关**：规则来源从 2026-12-11 起批量超期，其中三条引文已经和官方现文对不上（两条在 `rules/categories.yaml`，一条是内联规则）；发布流水线缺桌面依赖；broker 标准输出没有隔离；版本号不统一；分支领先 `main` 615 个提交。这些是 T02–T07（§8）。
9. **两项裁决都要先改治理措辞并另写安全设计**。这是 T01，由实施者起草、维护者审阅，本文没有动 `GOVERNANCE.md` 和 `SECURITY.md`。

### 1.2 代码评审要点

以下来自子代理通读，除注明外未逐项复核（审查）。

- **前端**：四种 UI 范式并存；`desktop/src` 有 51 条 import 指向 `design-previews`，其中 36 个未类型化 JS 模块（6,158 行）随产品发布；ESLint 配置忽略 `desktop/**`（实跑）；45 处字符串式 `invoke`；启动 JS 735.10 kB、gzip 241.25 kB，上限是 750 kB 和 250 kB（实跑）；没有 i18n。

`desktop/server/agent-stream.mjs` 116–143 行（实跑读源码）：

## 2. 竞品对标

### 2.1 Codex 与 Claude 桌面端

| 维度 | Codex 桌面端 | Claude 桌面端 | 本项目取舍 |
|---|---|---|---|
| 布局 | 侧栏（新建、搜索、插件、自动化，下面是项目和会话）＋对话＋右侧 diff、文件树、浏览器标签页 | 会话侧栏＋对话＋可拖拽分栏 | 采用三栏；右侧标签换成上线、依据、改动、开发者工具 |

以上为调研。两家的主题、命令面板、长会话虚拟化实现未核实。

### 2.2 垂直工具的交付形态

Expo、Supabase、Stripe 都以「MCP server ＋ skills」打包成 plugin 的方式交付垂直能力；Skills 是跨厂商的开放标准（调研）。这支持「规则内核进两家生态」的做法：已经在用 Codex 或 Claude Code 的人不需要装桌面端。

MCP Apps 在 Claude 桌面端可以渲染界面；Codex 和 Claude Code 是否渲染未核实，因此不依赖它。

### 2.3 官方工具现状

读到的官方页面里，开发者工具内嵌的 CodeBuddy 和 CloudBase AI Toolkit 都没有覆盖提审前合规检查（调研，非穷尽检索）。CloudBase AI Toolkit 做的是云开发资源的创建和部署，和本项目互补而不重叠（§4.4）。这个空档是本项目存在的理由，但它可能随时被官方填上，所以规则库的时效和依据质量比界面更重要。

## 3. 定位与可替代性

| 能力 | 通用 agent 能否替代 | 说明 |
|---|---|---|
| 读代码、改代码、跑命令 | 能，而且更强 | 不在这里竞争，做到够用 |
| 知道平台规则的大致内容 | 部分能 | 模型有印象，但没有核验日期和原文，会过时也会编造 |
| 带官方原文、链接、核验日期的规则 | 不能 | 66 条规则，每条有 `source_quote`、`official_url`、`last_verified`（实跑） |
| 上线阶段与下一步 | 不能 | `flow.yaml` 八个阶段，按主体类型筛选（实跑） |
| 拒因反查 | 不能 | 拒绝通知文本到规则的映射 |
| 不代办、不收集密钥、源码默认留在本机 | 通用工具不承诺 | `GOVERNANCE.md` 与 `SECURITY.md` 的硬边界 |

应做到的程度：一个第一次提审的个人开发者，装上之后不看文档，能在一次会话里知道还差什么、每一项的依据是什么、哪些可以让船友起草改动、哪些必须自己去微信后台做。

规则库的已知缺口：

- 66 条里隐私占 23 条、审核占 24 条；没有深度合成（AIGC）相关规则（实跑统计 `rules/`）。官方类目资质页现文有「深度合成」类目，含新增的「拟人化互动」一行，要求《互联网信息服务算法备案》等，可以作为补规则的来源（实跑读官方现文）。
- `category.education-hint` 的断言需要重判。规则引的是「适用于教育机构提供如课程销售、付费课程培训等服务」；官方现文里课程销售一行改成了「同时提供」备案核准或增值电信许可、经营范围含教育咨询服务、交易纠纷处理机制三项，「付费课程培训」的说法已经不存在（实跑）。这不是换个措辞就能过的，规则的 `warn`、`why`、`requires` 都要对照新原文重写。
- 课程类目新增了一句「如需实现安卓等非 iOS 端的小程序内购买交易，开发者需配置接入小程序虚拟支付功能并通过该功能实现」（实跑）。第三方资料称 2026 年 9 月虚拟支付向个人主体开放，这一点仍未核实，可能影响 `rules/payment.yaml`。

规则库这次暴露的问题比缺口更要紧：定时检查连续四个月失败没有人处理，三条引文已经和官方原文对不上而离线门禁仍然全绿（两条是因为门禁比的是 7 月抓的快照，一条内联规则根本不在门禁内）。这正是产品向用户承诺的那件事，所以 T04、T05 排在所有新功能之前。

## 4. 官方工具接入

### 4.1 三层方案

| 层 | 工具 | 做什么 | 是否默认 | 前提 |
|---|---|---|---|---|
| 一 | 开发者工具 CLI V2 / HTTP V2 | 检测登录、打开项目、预览、构建 npm、上传体验版 | 连接默认提供；上传默认关闭（§4.3） | 用户在开发者工具「设置 → 安全设置」开启服务端口，并已登录 |
| 二 | 开发者工具 MCP（`wechatide mcp`） | 读控制台、模拟器截图、自动预览 | 可用后接入 | 官方文档写最低 Nightly 2.02.2607032；Stable 是否提供未核实 |
| 三 | `miniprogram-ci` | 无开发者工具环境下的预览和上传 | 可选组件，按需下载 | 需要代码上传密钥和 IP 白名单 |
| 辅 | `miniprogram-automator` | 按路径点击走查、体验评分 | 随第一层 | 需要 `autoAudits: true` 才有体验评分 |

### 4.2 为什么这样分

- **第一层不经手任何凭据**。用的是用户自己登录的开发者工具，船友只发本机指令。上传体验版走这一层，是唯一不需要收集密钥的路径。
- **第二层最省事但还不稳**。官方 MCP 的只读工具有 `check_devtools_status`、`get_app_console_content`、`automation_viewport_action --action screenshot`；会改动的有 `auto_preview`、`buildnpm`、`project_open_window`；上传和云部署会由开发者工具自己弹确认。新的 `clientName` 首次连接会弹授权框，文档没有限制客户端（调研）。
- **第三层不进默认包**。`miniprogram-ci` 最新版 2.1.31，20.5 MB，182 个直接依赖（调研）；而且它要求用户把上传密钥交给本应用，与「不收集密钥」的方向相反。它的 `checkCodeQuality` 是否上传源码未核实。
- **没有任何一层能提审或查审核状态**。官方 MCP 没有提审工具；`wxa/security/get_code_privacy_info` 需要第三方平台授权，普通小程序不能调用；没有找到普通开发者可用的审核状态接口（调研）。这与「不代办」一致，界面上要说清楚：提审和发布由用户在微信后台完成。

### 4.3 上传体验版（已裁决：做）

相关原文有三处（实跑读文件）：

- `GOVERNANCE.md`：「不接代办 —— 不代替用户在官方后台注册、认证、备案、提交类目/隐私声明、发布。」
- `GOVERNANCE.md`：「不上传源码 / 不收集密钥 —— 预检默认本地执行。」
- `SECURITY.md`：「MCP 适配层不得新增远程上传能力；未来若支持远程服务，必须另写安全设计、默认关闭、显式开启。」

上传体验版不在「代办」列举的动作里，也不经手密钥；但代码确实离开了设备，「不上传源码」这句话的读者不会去区分「传给本项目」和「传给微信」。所以做法是先把话说清楚，再做功能：

- **先改措辞**（T01）：把「不上传源码」改成说得准的版本，即源码默认留在本机，本项目不运营任何接收代码、报告或密钥的服务器，例外只有用户显式开启的两项（agent 模式、上传体验版），都默认关闭。`SECURITY.md` 的 local-only 默认原则和对 MCP 适配层的限制不变。
- **实现约束**：默认关闭，在设置里显式打开；每次上传都弹确认，写明三件事（由本机开发者工具执行、只生成体验版不提审、代码会离开此设备发给微信）；权限档位不影响它，「自动应用修改」档下也要确认；模型不能自行触发，必须有用户的一次点击；MCP 适配层不暴露这个能力。
- **不变的边界**：上传体验版不是提审，也不是发布。提审和发布仍然只能由用户在微信后台做。

预览图 `shell-04-devtools.png` 里的确认卡就是按这组约束画的。

### 4.4 云与后端

从提审的角度看，后端只需要回答三个问题：域名和证书是否满足平台要求；云开发资源和代码里的调用是否对得上；审核员来看的时候后端是否可用。按「要不要凭据、会不会写入」分四层：

| 层 | 做什么 | 凭据 | 默认 | 结论 |
|---|---|---|---|---|
| 一 域名与证书就绪检查 | 对预检扫出的请求域名，核对协议、是否 IP 或 localhost、端口写法；用户点击后联网探测 TLS 版本、证书有效期、信任链、是否自签名 | 不需要 | 静态部分随预检；联网探测每次由用户触发 | 接，自己实现 |
| 二 CloudBase MCP 只读 | 列出云环境、云函数、数据库集合等元数据，对照代码里的调用 | 用户在 CloudBase 自己的设备码或浏览器登录，凭据由它自存，本应用不读不存 | 关闭，按项目开启 | 接，宿主做工具白名单 |
| 三 开发者工具的云开发命令 | 旧 CLI 的 `cloud env list`、`cloud functions list`、`cloud functions info` | 用户已登录的开发者工具 | 随开发者工具连接 | 接，只接这三条只读命令 |
| 四 其余云与服务器工具 | 微信云托管 CLI、腾讯云 COS / Lighthouse / 云数据库 MCP、EdgeOne Pages、SSH 或数据库直连 | AppID 加 CLI 密钥，或 SecretId / SecretKey | — | 不接 |

**第一层的依据和做法**。官方「网络」文档现文写明（实跑读官方现文）：域名只支持 `https` 和 `wss`；不能用 IP 地址或 localhost；必须经过 ICP 备案；TLS 必须支持 1.2 及以上；证书必须被系统信任、在有效期内、信任链完整；iOS 不支持自签名证书；配置了端口就只能向该端口请求，没配置时 URL 里连 443 也不能带。前三条现有规则已覆盖（`rules/domains.yaml` 四条加两条内联规则），后几条静态扫描看不出来，只能握手探测。

探测要守四条线，因为域名取自被扫描的源码，是不可信输入：

- 只做 TLS 握手并读证书，不发 HTTP 请求体，不跟随跳转。
- 只连公网地址，解析到内网或回环地址的一律跳过并说明原因。
- 每次由用户点击触发，不随预检自动跑。`SECURITY.md` 写的是预检默认不联网。
- 结果只说「满足 / 不满足 / 无法判断」和依据，不下「可以通过审核」的结论。

ICP 备案没有找到普通开发者可用的官方查询接口（调研；工信部站点抓取返回 521），所以只给人工核对的入口和要核对的内容，不自动判定。

**第二层的依据和做法**。`@cloudbase/cloudbase-mcp`（2.37.6，MIT，在维护）登录走设备码或浏览器，不需要用户把密钥交给宿主；它支持小程序云开发环境（调研）。但它有 44 个工具，只有 `query*`、`read*` 是只读的，其余会写入或部署；它没有全局只读模式，开关只到插件级，官方文档自己说那是「护栏，不是安全边界」（调研）。所以：

- 宿主维护一份逐个审过的工具白名单，白名单之外的工具模型根本看不到。清单在实施时对照当时的工具文档定，不照抄本文。
- 能读数据库记录内容的工具（`readNoSqlDatabaseContent`、`queryPgDatabase`、`queryMysqlDatabase`）首版不放行。读记录等于把用户的业务数据发给模型服务商，这比读源码更敏感，以后要做须另行裁决。
- `auth` 工具会返回明文临时密钥，不放行。登录由用户在界面上点击触发，宿主直接调用，结果不进对话。
- 只用本地 stdio，不用官方的远端 HTTP 端点；遥测默认开启，启动时用它的环境变量关掉；版本固定。
- 作为可选组件按需获取，不进默认安装包。它是新的生产依赖，引入前要维护者批准（§10）。

**第三层**。开发者工具新的 `wechatide` Skills 也覆盖云环境、云函数、云数据库、云存储，写操作由开发者工具自己弹确认，但需要 Nightly，工具名和只读子集未核实；等它稳定后并入 §4.1 的第二层。旧 CLI 的 `deploy`、`inc-deploy` 会部署，不接。

**第四层为什么不接**。微信云托管 CLI 登录必须给 AppID 和 CLI 密钥，与「不收集密钥」直接冲突，而且最新版停在 2023-11；腾讯云的 COS、Lighthouse、云数据库 MCP 都要 SecretId / SecretKey 并且会写入；EdgeOne Pages 只做部署（调研）。服务器 SSH 和数据库直连是通用运维，不在「上线合规」范围内，凭据风险又最高。用户需要这些能力时，应该在自己的 Codex 或 Claude Code 里配。

**审核员访问时后端是否可用**这个问题不靠工具回答。它进提审材料包（功能 3）的检查清单：测试账号、测试数据、审核期间服务不能下线，由用户自己确认。

第二、三层连通之后能对出来的问题大致是「代码调用的云函数在环境里不存在」「代码写的环境 ID 不在账号下」这一类。具体能对出多少取决于白名单里最后留下哪些工具，这一点未核实，功能 11 动手前先做一次只读探查。

## 5. 保留的 agent 基本操作

| 操作 | 范围 | 边界 |
|---|---|---|
| 读取与搜索 | 读项目内文本文件、按名称和内容搜索 | 沿用 `SECURITY.md` 的私有文件排除清单；不读项目目录之外 |
| 修改文件 | 生成改动，按文件过目 | 写入前自动存检查点；可按文件撤销或回到检查点 |
| 运行命令 | 白名单内的构建和检查命令（如 `npm run build:weapp`） | 不提供通用终端；白名单外一律拒绝，不是「询问后放行」 |
| 权限档位 | 只读 / 逐项确认 / 自动应用修改 | 没有「完全访问」；命令在任何档位都要确认，除非用户对本项目选了「始终允许」 |
| 计划清单 | 多步任务先列计划，逐项标记 | 只展示，不需要用户逐步批准 |
| `/` 命令与 `@` 文件 | `/check`、`/explain`、`/materials`、`/rewind`、`/compact`；`@` 引用项目文件 | 命令集固定，不做自定义命令 |
| 图片附件 | 贴拒绝通知截图、界面截图 | 只发给用户所选的模型服务商 |
| 消息排队 | 运行中可以先写下一条 | 可编辑、可移除 |
| 长对话压缩 | 接近上限时自动压缩，也可手动 | 输入框里有用量环 |
| 项目说明 | 读取项目根的 `AGENTS.md` | 只读 |

任何档位都不提审、不发布。这句话在权限菜单底部和输入框下方各出现一次，属于需要保留的后果提示。

### 5.1 分档（已裁决）

现状（实跑读 `agent-stream.mjs` 与 `docs/12-current-capabilities.md`）：模型拿不到源码。读取与摘要分享分别授权、默认关闭；关闭分享时模型只收到固定提示，开启时也只发送经 Schema 校验的有界摘要。

一旦 agent 能读文件、起草改动，文件内容就会发给用户自己配置的模型服务商。这是所有编码 agent 的工作方式，没有绕开的办法。所以做成两档，由用户按项目选：

| 档 | 模型收到什么 | 能做什么 | 默认 |
|---|---|---|---|
| 摘要模式 | 有界摘要，不含原始代码 | 解释、导航、交接给外部工具 | 是 |
| agent 模式 | 它读取的文件内容 | §5 表里的全部操作 | 否，按项目显式开启 |

开启 agent 模式的那个界面要写明文件内容会发给哪一家服务商，并且可以随时关回去。

安全设计（T01 起草，维护者审）至少要满足下面这些，它们不是可以在实现时再商量的：

- 私有文件排除清单在本机强制，读、搜、改三类工具走同一道检查，不靠提示词。两份清单先合成一份（T08）。
- 路径由本机解析：规范化之后必须落在项目根内，不跟随指向项目外的符号链接。`agent_tools.rs` 现有的原则「模型输入不决定项目路径」保持。
- 写入前存检查点；写入原子化；多文件改动要么全部落盘要么全部不落；撤销时比对哈希，文件被外部改过就停下来让用户决定。
- 命令白名单在本机定义，模型不能扩展；以参数数组执行，不经 shell 拼接。
- 项目文件、控制台输出、云端元数据都是不可信输入，它们不能提升权限档位，也不能触发上传。
- 密钥不读、不存、不回显；对话和工具结果只存本机。

命令产生的文件（例如 `dist/`）不在检查点内，界面用 info 提示说明。

**引擎改动**：放宽 `maxOutputTokens`、步数和工具调用上限；增加读文件、搜索、改文件、运行命令四类工具；扩 `agent_tools.rs` 的 `Permission` 结构；接入 MCP 客户端以连接开发者工具和 CloudBase。AI SDK 的 `createMCPClient` 是否在 6.x 稳定可用未核实，动手前先验证。

**不做**：通用代码编辑器、通用终端、第三方 MCP 插件市场、自建插件体系、子代理、云端任务。

## 7. 技术选型与前端收敛

| 决定 | 理由 | 证据 |
|---|---|---|
| 不嵌入 Codex app-server 或 Claude Agent SDK | Claude Agent SDK 非开源、受商业条款约束，再分发权利和自定义 base URL 未核实；Codex 是否仍支持 Chat Completions 未核实，这决定国内服务商能否使用 | 调研 / 未核实 |
| 继续用 AI SDK 6.x 自有循环 | 已在用（`ai` 6.0.313），支持多服务商；改动面最小 | 实跑 |
| 保留 Tauri 2.x、Node broker、rusqlite | 没有发现必须更换的缺陷；问题在加固而非选型 | 审查 |
| 规则内核走 MCP server ＋ plugin ＋ skill | 与 Expo、Supabase、Stripe 的交付方式一致 | 调研 |
| 扫描器从正则升级到 AST（`@babel/parser`） | 覆盖别名、解构、`wx["x"]` 这些正则盲区；行号不必等它 | 审查 |
| 首发只做 Windows x64 NSIS | 单一维护者；macOS 签名需付费，你已说明需付费则暂不考虑 | 你的决定 |

**前端收敛方向**。实机现在有三套组件来源（实跑）：`desktop/index.html` 里 49 处 Web Awesome 标签；`desktop/src/components/ui/` 下 2 个文件用 Base UI；设置页用 React 和 Tailwind。外加 `design-previews` 里随产品发布的 36 个无类型 JS 模块。

建议收敛到已经存在的那条路，不引入新库：React ＋ Base UI 原语，组件源码放在 `desktop/src/components/ui/` 由项目自己持有，样式只写 `--ds-*`。这符合「复用成熟组件库、组件源码可控、不重复引入相似库」。对话相关组件（输入框、过程折叠、工具审批卡、流式 diff）参考 open-claude-ui（MIT）的做法移植，不把它当依赖引入。Web Awesome 随各界面迁移逐步退场。

两个必须带上的细节：输入框要防输入法误发送（`isComposing || keyCode === 229`）；流式输出不抢滚动（用户上翻后停止自动跟随）。

**质量门槛**（进 CI，替代目测）：

- `desktop/**` 纳入 ESLint 和类型检查；`design-previews` 的模块迁入 `src` 并加类型。
- 启动 JS 保持在 750 kB、gzip 250 kB 以内（现在 735 kB 和 241 kB，余量很小，新外壳必须按路由拆分）。
- 会话切换和首屏时间设上限并测量；两家竞品在这一项上都被批评过。
- 每个新界面过一遍加载、错误、空三种状态和键盘操作。

**建议的先后**

- CLI 与 MCP 先发，不等桌面端。它们不受外壳重构影响，也是最不可替代的部分。

**第三阶段**：对话层迁到 React、对标项补齐、AST 扫描、签名、端到端测试进 CI。

## 9. 上线与分发

| 渠道 | 状态 | 卡点 |
|---|---|---|
| npm 包（CLI ＋ MCP server） | 未发布 | 仓库私有时 provenance 不可用；私有仓库能否走 trusted publishing 未核实 |
| MCP Registry | 未登记 | 需要 `server.json`、`package.json` 的 `mcpName`，名字以 `io.github.<user>/` 开头；要求公开仓库与否未核实 |
| Claude / Codex plugin 与 skill | 未打包 | MCPB 清单用 0.4，官方 schema 仍指向 0.3，宿主是否接受 0.4 未核实 |
| Windows 安装器 | 本机验收过，未签名，无公开下载 | SignPath 免费签名要求公开仓库；公开前只能未签名加 SHA256，SmartScreen 会拦 |
| 文档站 | 无 | 没有核实到免备案且大陆稳定可达的托管 |
| macOS 桌面版 | 移出计划 | 用 npm 包和插件覆盖 |

仓库不公开期间能做的：把发布流水线、安装器构建、版本管理都准备好并在私有状态下演练。公开那天再打开签名和 provenance。

五人试用仍是 0 份。新外壳值不值得做，最便宜的验证方式是拿 `shell-preview.html` 给两三个目标用户看，问他们「下一步点哪里」，这比任何评审都有效。

## 11. 未核实清单

决策或动手前需要补查的事项，按影响排序：

- AI SDK `createMCPClient` 在 6.x 是否稳定可用（影响功能 6、7、11 的做法）。
- 开发者工具 MCP 是否进入 Stable 通道（影响功能 7 的时间）。
- CloudBase MCP 以小程序身份登录的实际流程；白名单里能留下哪些工具；`queryCloudRun` 能否读到微信云托管；`wechatide` 云开发工具名与只读子集（影响功能 11）。
- 2026 年 9 月虚拟支付向个人主体开放的说法（影响 `rules/payment.yaml`）。
- `miniprogram-ci` 的 `checkCodeQuality` 是否上传源码。
- 私有仓库能否发 npm、能否登记 MCP Registry。
- MCPB 0.4 清单的宿主兼容性。
- Codex 是否仍支持 Chat Completions；Claude Agent SDK 的再分发条款。
- broker 标准输出污染：Node 侧已实跑复现；Rust 侧「读到非 JSON 行即断开」仍是读源码得出，整条链路没有端到端复现。
- 两条登录规则即使降为 `draft`，`rule-rot` 的链接体检仍会因社区帖的登录墙而失败（读 `scripts/rule-rot.mjs` 推断，未实跑；T04 里交维护者定）。
- §1.2 里未标「实跑」的代码评审数字来自子代理，没有逐项复核。

上一版清单里的两项已实跑，移出本清单：「`release.yml` 会失败」已在本机复现；「NSIS 是否接受预发布版本号」的结论是 NSIS 接受、MSI 拒绝，所以 T06 要把 `targets` 从 `all` 收窄为 NSIS（§12）。
