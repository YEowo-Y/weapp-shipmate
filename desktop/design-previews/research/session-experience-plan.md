# 会话导航与草稿连续性优化计划

日期：2026-10-17。范围：`chat-full.html` 本地交互原型。

## 证据与最小范围

- 当前会话切换只保存 draft/edit，DOM 中的文件引用被清空；页面级 pendingScenario 也被重置，导致恢复的故障演示草稿与执行状态不一致。
- Claude 官方帮助说明侧栏会话右侧菜单提供重命名；OpenClaw 官方 Chat 文档区分会话搜索范围、首次输入命名和显式名称。Cherry Studio 官方 README 展示实际产品页面并列出全局搜索和话题管理。只借鉴交互与层级，不复制 AGPL 产品实现。
- 保留现有原生 ESM、Lucide、共享 menu/dialog/composer；不增加依赖、不更换技术栈。

## 修改顺序

1. 用回归测试锁定会话 A/B 的草稿、引用、演示场景隔离及切换行为，再修改页面适配器。
2. 将文件引用与待执行场景归属到 session；使用同一引用渲染入口，确保删除、去重、新建、恢复一致。
3. 增加范围明确的本页会话搜索（标题与消息正文）、首次发送自动命名、侧栏菜单与原生对话框重命名。显式名称不被后续消息覆盖，空名称不接受。
4. 新会话使用真实空状态与可编辑的任务建议，不插入虚构 assistant 消息。建议仅填入草稿，不直接执行。
5. 用现有中性色、文本层级、Lucide 图标和紧凑会话行统一视觉。键盘、触摸、窄屏入口均可达。

实施核对：现有 `createDemoPlan` 只提供固定隐私预检和故障场景。最终任务建议收敛为预检与审阅、失败重试、超时恢复，各入口匹配已有执行能力，不暗示可回答任意类目问题。

## 验证与边界

- 测试 A/B 往返、独立引用与删除、场景只消耗一次、无效会话 ID、首条消息命名与手动名称保护、搜索范围、重命名取消/校验、空状态建议。
- 运行完整测试、lint（显式包含预览 JS）、desktop build、静态页面引用及 HTTP MIME 检查。
- 浏览器访问仍按用户选择禁用；本轮只做代码与自动化验证。视觉、原生弹层焦点与实际响应式验收保持 BLOCKED，不声称达到像素级一致。
- 所有会话仍只在当前页面内存中；刷新清空。没有真实模型接入、文件读取、持久化或后台 Agent 执行。本轮不修改这些边界。
