# 功能呈现与阅读体验规范

调研日期：2026-10-23。适用于上线船友现有 Tauri + TypeScript 桌面端。此文区分本轮实现、后续设计要求与尚未验证事项，不把社区讨论当作强制标准。

## 依据与取舍

| 实际查阅来源 | 采纳到项目 | 适用限制 |
| --- | --- | --- |
| [WCAG 2.2](https://www.w3.org/TR/WCAG22/)：1.4.1、1.4.10、1.4.12、4.1.3 | 状态不只靠颜色；窄窗重排；文字间距变化不截断关键内容；异步反馈不随意抢焦点 | 本轮只验证相关路径，不宣称产品整体满足 WCAG；1.4.8 的行宽要求属于 AAA |
| [USWDS Typography](https://designsystem.digital.gov/components/typography/) | 正文以已有 16px 偏好为基准，控制行宽，左对齐，标题上方留出分组空间 | 英文字符行宽不机械套用中文；正文约 32–40 个汉字为本项目起点，不是通用标准 |
| [GOV.UK Details](https://design-system.service.gov.uk/components/details/) | 折叠只承载补充摘录、版本记录与原文；结论、适用性、必要操作常显 | 不把多数用户需要的信息藏入折叠，也不复制政府网站的品牌视觉 |
| [GOV.UK Notification banner](https://design-system.service.gov.uk/components/notification-banner/) | 当前任务信息放在内容中；错误紧邻动作；避免堆叠相互竞争的提醒条 | 风险内容需要保留，但不等于每段都加警告色块 |
| [WAI Complex images](https://www.w3.org/WAI/tutorials/images/complex/) | 流程用图标与等价文字说明；数据图需同时提供可读解释 | 三步阅读引导使用语义有序列表即可，不引入图表或流程编辑库 |
| [Web Awesome Details](https://webawesome.com/docs/components/details) | 复用已安装 Web Awesome 按钮与现有原生 dialog/details，保留标准键盘行为 | 仓库锁定 3.14.0；在线文档不保证与锁定版本相同，不采用未核验新 API |
| [Web Awesome 社区 #1456](https://github.com/shoelace-style/webawesome/issues/1456) | 在圆角、滚动容器内检查 summary 的键盘焦点是否裁切 | 历史 beta 问题，已关闭；不能据此声称当前版本仍有缺陷 |
| [GOV.UK Task list 社区 #5990](https://github.com/alphagov/govuk-design-system/issues/5990) | 长标题与状态窄屏换行；文字放大测试；完成状态必须来自真实记录 | 讨论中的尺寸与案例不是普遍硬性规范 |

本轮复用现有源码与依赖，不复制上述设计系统代码，不新增包或字体。社交图片中的“统一字重减 40”“全部去边框”“逐字模糊”不作为规范：可读性、焦点与性能优先，已有中性色和用户字号继续生效。

## 产品内容结构

统一顺序为 **当前结论 → 影响与下一步 → 具体依据 → 来源与时效**。这是本项目的信息架构决定，不是上述标准规定的固定模板。

长内容采用有界阅读区域；摘要与原始内容必须指向同一份成果。用户可以回到工具配置、完整报告和修复交接，不因阅读而执行工具、发送模型请求或改变完成状态。历史内容明确显示保存时间与有效性，不把过去成功写成当前检查通过。

### 功能呈现矩阵

| 功能 | 首屏应呈现 | 补充内容 / 图文方式 | 用户主路径 | 本轮状态 |
| --- | --- | --- | --- | --- |
| 代码预检、上线清单、拒因反查 | 成果身份、核对项概览、条件适用性、扫描限制、待处理要求 | 目录；官方摘录可展开；图标配文字的阅读路径 | 生成 / 历史重开 → 阅读 → 依据 → 交接或复查 | 独立阅读视图实现 |
| 修复交接 | 来源性质、问题依据、期望结果、验证步骤 | 版本明细可展开；Markdown / JSON 导出 | 从报告准备 → 人工阅读 → 导出 | 正文排版与字号统一；复用原流程 |
| 首页工作台 | 当前项目、一个明确开始动作、最近成果与未完成事项 | 简短功能说明配已有 Lucide 图标 | 选项目 → 预检或清单 → 阅读结果 | 已按当前项目、开始任务、继续处理重排；导航不执行工具；见后续呈现记录 |
| 项目健康 / 后台维护 | 当前配置、最近真实结果、是否正在监听、可关闭入口 | 展开执行范围与平台限制 | 查看状态 → 定位问题 → 打开报告或设置 | 延用现有实现，后续按此规范逐项验收 |
| 上线进度 | 下一步、未确认事实、人工确认状态 | 分阶段任务；长标题可换行 | 补事实 → 查看要求 → 人工确认 → 重算 | 已增加实际统计、下一步定位及临时草稿冲突恢复；人工记录不代表官方通过 |
| 官方资料 | 最近尝试与上次有效结果分开、来源是否变更、手动检查入口 | 资料地址、哈希、时间为补充明细 | 看状态 → 核对来源 → 必要时重新预检 | 延用现有实现 |
| 会话、历史、项目成果 | 标题、所属项目、时间、草稿/运行状态 | 搜索命中片段；不靠颜色区分历史和当前 | 搜索 → 打开 → 恢复上下文 → 阅读成果 | 保留现有历史路径；新增阅读入口 |
| 模型连接与权限 | 当前连接方式、可用模型、下一步、明确失败原因 | API/OAuth 的字段与权限说明按方式渐进展示 | 选厂商 → 连接 → 验证 → 选模型 | 延用现有实现；不在本轮变更认证 |
| 偏好与通知 | 当前选择、保存反馈、系统权限与应用开关的区别 | 可展开平台限制与帮助 | 修改 → 立即反馈 → 验证或恢复 | 已分组导航、主题预览和常驻保存反馈；复用原有通知控制器 |
| 空状态 / 错误 | 当前缺少什么、一项可执行恢复动作 | 简单图标配文字；保留上次结果并标清 | 补前置条件 / 重试 → 恢复原任务 | 阅读无数据、旧数据与链接失败覆盖 |

## 本轮交互与组件合同

后续三个页面的依据、组件选择和用户路径见[功能页面呈现设计](feature-presentation-design-20261023.md)，实际验收见[呈现交付记录](feature-presentation-delivery-20261023.md)。

- “阅读报告”与首页最新报告打开同一阅读模块；报告工具栏仍可复制原文、加入当前会话和创建交接。
- 宽屏正文约 640px，上限 40ic；目录与正文分列。窄窗单列，目录可折叠，代码与表格只在自身区域横向滚动。
- 结构化摘要只读取既有校验通过的数据。条件自查单列统计，不算作已发现问题；空项不代表通过。旧报告或无效结构直接展示安全 Markdown 原文。
- 正文使用用户字号偏好；数字使用等宽数字；中性背景分层、必要边界和清楚焦点共同工作，不追求无边框本身。
- 三个图标步骤表示建议阅读顺序，不是执行进度、任务完成率或模型隐藏推理。图标保持装饰语义，文字提供完整含义。
- 关闭回到可见入口，目录跳到实际标题；外链由已有系统浏览器通道处理，失败允许重试；无自动网络请求。
- 源报告变化时保留已打开快照，但禁止将当前阅读交接到另一份报告；项目切换关闭阅读，避免混淆归属。

## 验证计划与边界

基线 64 项报告、交接、Markdown 与工具面板回归通过。新测试覆盖结构摘要、旧原文、安全内容、无结果、扫描限制、快照/焦点与入口不触发执行。完整 Node 测试、仓库 lint、TypeScript/Vite 构建及 Windows 原生隔离验收执行后，结果记录在同目录交付报告中。

原生验收使用真实 Tauri/WebView2 和 EdgeDriver，预检/导航/拒因均走实际本地工具与 SQLite。检查历史重开、重启恢复、目录、交接、复制、深浅色、窄窗、18px 与 200% 文字压力。此前 Work 浏览器权限受限，不绕过；原生验收不等于独立浏览器矩阵或读屏软件认证。
