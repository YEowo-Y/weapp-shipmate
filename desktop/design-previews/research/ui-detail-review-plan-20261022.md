# 图片建议与项目体验评审计划

依据用户图片中的十条建议，核对当前实现、官方平台规范和开源产品源码。图片是调研输入，不视作必须照搬的规范。继续使用既有 Vanilla TS / Vite / Tauri、Web Awesome、Lucide、markdown-it，不安装依赖。

## 实施前结论与范围

- 复制成功状态目前永久保留，使旧消息的操作栏一直显示。复用当前复制状态控制器，成功约 2.5 秒后恢复原控件；错误保留可重试。覆盖重复复制、切换会话、重绘、销毁与迟到 Promise。
- 流式已保留 Markdown 节点，但每一个 delta 都立即解析/布局。评估按浏览器绘制帧合并视觉更新，同时消息模型与存档保持即时，停止/完成/切换时刷新或取消，避免丢末尾内容。禁止逐字 DOM/模糊滤镜和人为延迟真实输出。
- 首页卡片及代码块存在多层边框；复用现有 surface 令牌减轻静态容器装饰，保留输入、错误、选中和键盘焦点边界。只改共享组件，不整体换肤。
- 动态时长/结果计数补 tabular-nums，正文使用渐进增强 text-wrap: pretty。当前系统字体未声明可变字体轴，不统一减 40 字重；行内 SVG 与 flex 图标分别处理。
- 原生 details 继续负责键盘与隐藏语义。未有实际需求的拖拽/点赞不新增；不为套用图片引入动画库。

## 职责与验证

主代理负责全项目评审记录、共享 CSS、原生验收及集成；独立子代理只读研究/映射；实现代理限定 conversation.js 与对应交互测试。先固定行为测试再改状态，保留已有脏工作区。

风险 high（共享消息呈现与跨入口状态）。运行针对性回归、全量测试、lint、TS/Vite/Tauri 构建和既有 Windows 原生脚本。浏览器目前被 Work 设置禁用，不绕过；以原生 WebView2 检查实际视觉、复制恢复、流式停止和窄屏，浏览器缺口单列。每次视觉编辑以前轮真实截图为基线，最终保留截图与状态 JSON。不变更鉴权、数据格式、模型协议或权限，不发布。
