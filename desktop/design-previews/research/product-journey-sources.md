已先阅读 [已有产品研究](agent-product-reference.md)、[输出组件研究](agent-output-sources.md)、[服务商打磨记录](provider-polish-report.md) 与 [产品愿景](../../../docs/08-product-vision.md)。沿用其中已核查的源码、许可和 REA 证据，不重复声称本轮执行了 REA。**本轮证据是成功读取的官方文档和文档中的示例描述；未启动这些产品、未在它们的真实客户端完成交互或新拍截图。** 当前项目的浏览器检查另由本轮实施记录负责。

## 8 项当前证据与适用范围

### 1. Codex 所在桌面产品：先选工作上下文，再发起任务

来源：[OpenAI 桌面应用文档](https://learn.chatgpt.com/docs/app)。原地址 `developers.openai.com/codex/app/` 本次已重定向至该页；当前页面标题为 ChatGPT desktop app，正文仍明确列出 Codex 的 New chat 入口。不能把它称为独立旧版 Codex 的最新逐像素设计稿。

**文档事实：**快速开始依次选择工作位置、开启会话、提供目标与上下文；文档强调在同一工作空间切换项目并查看实际输出。

**本仓建议：**`first-run.html` 应把用户带到匹配的上线前或上线后工作区，并明确下一步；`main-four-region.html` 应说明当前项目、当前阶段和主要动作。设计索引是评审入口，业务页面还需要直接返回工作区的路径，不能要求用户反复经过十四页目录。

### 2. Codex / ChatGPT 项目与会话：导航组织不等于权限或进度

来源：[Projects and chats](https://learn.chatgpt.com/docs/projects)。从官方桌面文档链接进入，旧 `/codex/projects` 也重定向至此。

**文档事实：**项目保存相关会话和共享上下文，不同目标使用独立会话；短而描述结果的标题、搜索、置顶与归档用于找回工作。置顶仅改变位置，不扩大可访问内容。

**本仓建议：**工作区、阶段、对话和设置应采用稳定名称与当前位置标识；切换视图保留项目与草稿归属。固定示例项目不能展示成已选中的本地目录。状态应来自实际事件，不能把“完成注册”之类会话标题当作阶段完成。

**资料限制：**本次页面重复了一组组织会话段落，并对搜索快捷键给出不同口径；不据此改动本仓已验证的 Ctrl/⌘K 命令面板。

### 3. Claude Artifacts：成果独立，错误恢复回到对应内容

来源：[What are artifacts and how do I use them?](https://support.claude.com/en/articles/17153992-what-are-artifacts-and-how-do-i-use-them)。

**文档事实：**可编辑、复用、再次访问的成果在对话旁打开；成果与会话关联。错误旁提供修复入口，将错误信息带入新消息，再由用户发送。文档区分新模板与旧 artifacts，不能照搬历史教程的全部操作。

**本仓建议：**核查摘要留在主阅读区，规则依据、完整结果和文件差异按需打开；打开成果应明确标题、来源及返回路径。解释拒审与审阅错误应在错误旁给明确下一步；查看详情、复制和重试应是不同动作。未实际生成的文件、尚未写入的差异不能标作已保存成果。

### 4. Cherry Studio：配置完成和模型可用之间有明确步骤

来源：[Model Service Settings](https://www.cherryai.com/docs/en/pre-basic/settings/providers/)。

**文档事实：**密钥单独进入弹窗；地址、模型清单与连接检查分开。同步发现的模型需要加入清单，服务商还需启用，才进入对话选择。

**本仓建议：**沿用已有服务商列表、详情、凭据弹窗；保持“草稿已添加”“格式有效”“连接通过”“可用于对话”四者分离。首次引导无需强迫先填密钥；本地规则能力和示例体验应有可理解入口。当前预览没有连接测试或安全存储，就不能以保存按钮制造已连接状态。

**取舍：**不照搬 Cherry 的地址尾缀约定、多密钥轮询或 AGPL 源码；这些不是本次路径打磨所需能力。

### 5. OpenClaw：执行、草稿、错误和恢复各自有边界

来源：[Control UI — Chat](https://docs.openclaw.ai/web/control-ui/chat)，重点为 Chat behavior、Stop and abort、Send and history semantics。

**文档事实：**运行进度留在会话内，输入区保留停止控件而不重复 Working 行；展开工具可看输入与结果，完成答案保持可见。终态错误保留部分输出；详情或复制不触发重试；重试等恢复动作保留未发送草稿。停止与排队的作用域由真实运行身份确定。

**本仓建议：**继续使用现有 run ID 与公开执行摘要；同一运行只保留一处主要动态提示，符合用户要求的文字渐变、不叠加圈圈。失败、停止、待审批均不能涂成成功。页面动作产生新请求时不得覆盖草稿；无真实队列和网络时不提供虚假的排队、在线、重连反馈。原生示例的重试含义应按现有执行器定义，不冒充 OpenClaw 的继续执行语义。

### 6. assistant-ui：保护正在阅读的内容

来源：[Thread primitive](https://www.assistant-ui.com/docs/primitives/thread)。之前尝试的 `/docs/guides/Thread` 本次失败，后改用官方有效 primitive 页面。

**文档事实：**用户上翻时停止自动跟随；展开工具详情会暂停跟随，回到底部或使用返回最新控件可恢复。输入区高度参与滚动计算，避免遮住对话。组件提供空态、消息、建议和滚动区域的职责分离。

**本仓建议：**核对 `conversation.js` 已有的阅读保护在主工作区、完整对话及窄屏下是否一致；长工具内容和审批区不应挤掉正文或输入区。空态建议要能走通实际演示动作，不能只作装饰。当前无需引入 React runtime 来重新实现已具备的行为。

### 7. AI Elements Tool：状态不只是运行 / 完成

来源：[AI Elements — Tool](https://elements.ai-sdk.dev/components/tool)。

**文档事实：**示例区分参数生成、运行、请求审批、审批响应、完成、错误和拒绝；详情分成输入与结果/错误。错误示例默认展开。

**本仓建议：**复用现有 `components/message.js` 和 `presentation.js` 状态定义；审批响应不能直接代表工具成功。成功摘要可轻量折叠，错误与需要用户动作的状态要可见。本仓成功工具默认折叠是阅读密度取舍，不宣称照搬上游“完成后默认展开”的示例行为。

**更新提醒：**本次页面顶部明确说明 AI Elements 正迁入 shadcn/ui，原项目计划于 **2026 年 11 月底**弃用。不要沿用旧安装命令作为新选型结论。

### 8. shadcn/ui 当前 AI Elements：用共享基础组件组合模式

来源：[shadcn/ui — AI Elements](https://ui.shadcn.com/docs/ai-elements)，由上项迁移提示直接进入。

**文档事实：**当前定义是基于 shadcn/ui 的界面组合模式：Chat 由消息与滚动器组成；工具、计划和执行步骤使用共同 Trace 形态。已有复制入项目的组件可继续使用，不强制迁移。

**本仓建议：**先统一本仓已有消息、工具、结果、审批、弹窗和导航的基础视觉与行为，避免每个业务页再写一套相同控件。若正式桌面入口未来确需迁入 React，再单独核对当前组件 API、许可、依赖和迁移成本；本轮没有安装 shadcn 或宣称已获得其 runtime 能力，也不展示模型隐藏推理。

## 本轮优先级建议（项目推断，尚非完成事实）

1. **入口与返回路径。** 每个业务页明确所在工作区、当前任务和下一步，初次引导的选择应影响目标页面；目录留作评审工具。
2. **任务路径连贯。** 预检 → 问题解释 → 修复建议 → 差异审阅 → 复查应有清楚的前后关系；示例审批不得声称修改过用户文件。
3. **状态可信。** 统一示例数据标记、可用/未连接状态、按钮禁用原因及恢复动作；删掉不能兑现的成功文案和无意义重复进度。
4. **阅读与输入连续。** 保留草稿、滚动和折叠状态；窄屏仍能看到主动作，弹窗有明确焦点返回。使用现有共享实现修正，避免重复协议与抽象。
5. **结果可用。** 摘要、依据、原始信息、成果分别有清楚层级；复制、打开、下载、重试动作与真实能力一致。未完成能力清楚解释，不借精致视觉掩盖空实现。

上述建议服务于本项目“小程序上线 copilot”的领域目标，不建议增加通用多 Agent 平台、插件市场、长期记忆或无业务需要的流程画布。正式交付应分别说明真实规则内核能力、可操作的本地演示、尚待接入的桌面能力。
