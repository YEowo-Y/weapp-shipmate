# 清单成果操作与阅读：实施计划

日期：2026-10-17。继续已授权项目开发；采用直接实施与有界原生子代理。保留全部已有工作区改动，不加依赖、不部署、不改变规则或模型/凭据服务。

## 问题与范围

真实本机清单的消息复制当前只复制摘要；数十条规则缺少查找入口，阶段details没有稳定标识，切会话后无法恢复展开位置。本轮完成同一结果的阅读和带走路径，不扩展项目文件权限、模型工具循环或持久化。

## 实现合同 / 复用与简化

1. 结果必须是完成的 guide 消息，guide输入与structuredResult双重校验；失败、停止、无效结果不导出。现有普通文本/代码复制保持原行为。
2. 新纯模块 `guide-artifact.js` 提供 `createGuideArtifact(input,result,format)`，format只允许markdown/json，返回 `{text,mimeType,filename}`。Markdown含明确输入、适用项、自查项、要求、来源、核验日期和非实时/未扫描说明；所有数据文本进行Markdown转义，链接只用已校验官方HTTPS。JSON保留原始runGuide结果合同；不包含聊天历史、草稿、模型配置或凭据。固定受控文件名，不使用用户文本作为文件路径。
3. 复用现有消息复制状态/迟到保护。增加可见成果按钮“复制清单”“下载 Markdown”“导出 JSON”，下载成功反馈只说“已发起下载”，不声称已写入磁盘。使用原生Blob/ObjectURL/临时下载链接，有限延迟撤销URL并在destroy/换会话/离页清理。
4. 清单卡增加有标签的search input、命中计数与空状态；同时搜索标题/规则ID/阶段名/要求/说明，过滤不改变原始数据和导出范围。复用STAGES阶段名称，删除另一份名称表。每个分区/阶段details有稳定唯一data-component，展开状态与搜索草稿纳入既有view state。
5. 搜索和展开不把对话滚回底部，不改草稿/模型/工具运行；IME组合期间不发布搜索，结束后更新，清空恢复完整清单。状态区使用polite，保持焦点和原生键盘行为。宽度继承消息列、工具栏窄屏可换行，不增加大弹窗或动画。
