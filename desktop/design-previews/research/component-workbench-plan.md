# 开源组件与工作台优化计划

日期：2026-10-20。用户要求真实组件标准化、开源集成、提高页面质感与功能可发现性。

## 边界、选型与验收

保留 Tauri 2 + Vanilla TypeScript / Vite 与共享浏览器预览。选择 Web Awesome Core 3.14.0（MIT）作为唯一新增 UI 组件库，按需打包按钮、标记、菜单和提示，本地加载，不使用运行时 CDN。继续使用既有 Lucide、品牌图标、Floating UI、安全 Markdown 和原生 dialog 生命周期。本轮不迁移 React、不引入额外聊天框架、不改认证或持久化协议。

风险为 high：共享组件与跨入口用户路径。验证依据为现有 package.json、desktop/package.json 和 scripts/desktop-native-e2e.mjs。先运行受影响基线，再验证功能入口、焦点、键盘菜单、真实成果状态、390/768/1280px 布局；执行全量测试、lint、TypeScript/Vite/Tauri 构建、Windows 原生验收和独立复查。比较构建体积、检查新增依赖的许可证与漏洞。仅作本地交付，不作 CI 或发布就绪声明。

## 顺序与职责

1. 阅读真实竞品图、官方库文档和当前代码。诊断功能入口与组件重复，不以添加装饰或模拟数据填满页面。
2. 主执行者安装固定版本开源库，提供可复现的本地按需构建、许可证与共享组件主题。
3. 正式桌面负责人改造首页、工具入口和当前报告入口，复用实际项目目录、主体、最近执行状态与模型连接；保留既有 DOM ID/存储和工具执行接口。
4. 浏览器工作台负责人使用同一组件和首页结构，突出清单、模型连接和当前成果入口；隔离演示操作，不伪造浏览器目录扫描。
5. 主执行者统一按钮、菜单、徽标、辅助文字与图标尺寸，完成浏览器和原生截图对比；按发现修复并复验。

## 共享设计约定

- 首页为左对齐的工作台内容，最大宽度 880px；对话和输入仍保持 704px 阅读宽度。
- 使用统一中性色和现有低饱和强调色，4px 间距体系、8/12/16px 圆角层级；正文 14px、辅助 12–13px，重要任务标题 18px、页面标题 28px。
- 两个任务为不等权的实用面板：项目预检说明输入与检查范围，上线清单说明主体、步骤与输出；不用大面积空白欢迎海报。
- 下方展示模型连接入口和真实当前成果状态；无报告写明尚未生成，有结果可打开原报告，不复制或虚构报告数据库。
- 交互使用 Web Awesome button/dropdown/tooltip/badge，业务容器使用语义 HTML 和共享 workbench.css；不要重复造菜单定位与键盘逻辑。
- 功能菜单仅列可执行动作；浏览器演示故障/示例文件不再混在主要业务入口。
- 保留服务商原图标、Lucide 白名单和显式文字；无额外旋转加载器，尊重 reduced-motion。

回退只涉及本轮新增包、vendor 产物和受控界面文件，不重置原工作区。没有数据迁移或删除。
