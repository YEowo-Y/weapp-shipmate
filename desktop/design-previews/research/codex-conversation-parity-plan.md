# Codex 对话体验对齐：实施计划

2026-10-17。承接 dialog-foundation，用户要求前端与交互整体对齐真实产品。保留原生 ESM、Floating UI、Markdown-it、Lucide、native dialog/popover；不引入第二套聊天框架。

## 参照与边界

- 视觉主基准为用户提供的 Codex 输入框/添加菜单/执行流截图；沿用此前实际查看的官方产品图，进一步核对公开文档。避免拼接未经证实的 Claude Desktop 或 CLI 行为。
- 官方当前桌面 Settings 有 follow-up 策略和发送方式设置；没有充分一手证据证明桌面 Tab 队列快捷键。本轮不伪装 steering/模型接入/持久化；生成中草稿应有明确反馈。
- 当前预览继续使用固定本地计划；引用只是路径上下文示例，不能呈现为已读取真实文件。
- 用户已选择本轮代码与自动化验证；视觉门禁 BLOCKED，不绕过 Work 浏览器禁用，不宣称像素一致。

## 改动前审计与清理计划

1. 视觉收敛：提高正文阅读字号，助手回复保持开放排版，移除每条回复重复的可见身份标签，保留可访问说明和页面演示标识；用户消息、引用、消息工具栏分别明确分层。旧消息操作按悬停/焦点显露，最新回复和触摸设备保持可见。
2. 状态与执行记录：保留基于真实演示事件的紧凑折叠工具行；运行中只用文字渐变，减少多余转圈、状态装饰；普通静态文字作为 reduced-motion/forced-colors 回退。统一成果、代码、引用和审批密度，不删除可追踪结果。
3. 输入区：保留 Codex 截图的两层输入结构、添加/只读状态、模型/发送停止位置；改善窄栏换行、触摸目标、与阅读区共同边界，补充可见且随状态变化的输入提示。
4. 功能连续性：保存/恢复会话阅读位置、跟随状态和展开详情；生成中 Enter 不静默吞掉，草稿保留且有说明；修复编辑旧消息与原草稿故障场景串用。
5. 请求上下文：发送时快照引用到对应用户消息，之后修改草稿不能改写历史引用；重新执行、编辑、切会话路径保持上下文所属关系。显示为只读示例路径，不读取文件。
