# 图片建议、开源实践与全项目体验评估

核验日期：2026-10-22。截图中的十条建议是设计假设，不是行业标准。评估以当前仓库、已有真实桌面截图、官方规范和开源实现为依据；本轮未取得新的 Codex / Claude 产品截图，不声称逐像素复刻。

## 总体判断与用户路径

当前项目适合继续沿用 Vanilla TypeScript / Vite / Tauri 2、Web Awesome Core 3.14.0、Lucide 和 markdown-it。已有成熟控件、主题令牌、消息控制器与会话存档，重建 React 界面或再叠加聊天组件库会增加维护面。现阶段最大的质量差距是行为反馈的一致性、真实能力边界和验证覆盖，并非缺少动画或依赖。

主路径保持「新任务 → 本机预检 / 上线清单 → 阅读报告 → 按需加入当前会话存档」。用户也可以连接模型发送文本问题；当前报告记录不会自动作为模型上下文，不能把存档衔接表述成模型理解报告。审核反馈可从拒因查询进入。历史搜索和模型设置属于持续可达的辅助入口。初始主页呈现任务和下一步，已有会话以阅读与输入为中心。

| --- | --- | --- |

## 截图十条建议的取舍

| 建议 | 判定与落地 |
| --- | --- |
| 1%–3% 色阶、全部去边框、禁纯黑 | 采纳减少装饰目标；首页静态卡片与代码块改用现有 surface-2，保留输入/选中/焦点及表格分隔。1%–3% 不是无障碍对比指标，必要控件视觉线索遵循 [W3C 非文本对比说明](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)。 |
| 焦点只能用双阴影 | 不采纳绝对规则。Windows 高对比模式会移除 box-shadow；保留 :focus-visible，新弱边界容器在 forced-colors 下使用 CanvasText。依据 [MDN forced-colors](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/forced-colors)。 |
| 暗色字重统一减 40 | 不执行。当前系统/CJK 字体未保证可变字重，360 可能匹配到更轻档位；按真实字体与角色评审，不能当成光学校正公式。依据 [MDN font-weight](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/font-weight)。 |
| 每字 90ms、6px blur、错开 30ms | 不照搬。保留现有执行文字渐变、即时输出及 reduced motion；不人为延迟响应。参考 [Streamdown Animation](https://streamdown.ai/docs/animation) 的新增内容独立动画原则，其默认是按词 150ms 淡入，blur 为可选。该资料不构成安装 React 依赖的理由。 |
| 图标统一 -.125em | 不全局覆盖。按钮图标由 flex/grid 居中，通用 app-icon 已有 inline-block 对齐；本轮删除首页图标外盒，保留 Lucide 尺寸。固定偏移需实际行内图标证据，不能改变所有按钮。 |
| 数字等宽 | 采纳。运行记录、结构化结果数量、清单分组/筛选计数补 tabular-nums；项目已有通用 .tnum。它不保证位数增加后宽度不变。依据 [MDN font-variant-numeric](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/font-variant-numeric)。 |
| Grid 0fr→1fr 折叠 | 保留原生 details/summary 和成熟组件。当前没有需要消除的 JS 测高路径，不新增折叠层。折叠可访问性与焦点隔离优先于动效。 |
| 所有正文 pretty | 限定用于静态首页简介/任务描述，作为渐进增强；不覆盖实时文本、代码和编辑器。[MDN text-wrap](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/text-wrap) 明确 pretty 需要更多布局计算。 |
| 两套固定弹簧参数 | 采纳动作应有区别的原则，不新增不存在的拖拽/点赞，不增加动画库。参数缺乏质量等上下文，不能作为跨产品规范。 |
| 复制 2.5s 自动恢复 | 采纳为项目统一时长。等待剪贴板成功后显示成功，2.5s 恢复原按钮；失败持续可重试。参考 [assistant-ui ActionBar](https://www.assistant-ui.com/docs/primitives/action-bar) 的可配置短暂复制状态，以及 [Cherry Studio CopyButton 固定提交](https://github.com/CherryHQ/cherry-studio/blob/41c240712e28ff03d17115e522a5394e605fe374/src/renderer/components/CopyButton.tsx#L25-L82) 的成功/失败分离。assistant-ui 默认是 3s，2.5s 不是行业标准。 |

## 已落实的行为修复

- 成功复制恢复原图标、文案、aria-label/title，不替换按钮，不丢焦点。重绘后恢复仍有效。
- 成功播报同样到期消退；以递增版本标记归属，旧计时器不会清除后续错误、任务状态或另一条相同复制提示。此项来自本轮真实桌面截图复核。
- 再次复制取消旧计时器；切换会话/销毁清理状态；旧 Promise 和旧 timer 不覆盖新任务。
- 复制流式代码后，代码本身变化立即撤销旧反馈。异步复制完成也核对源码快照，不能把旧片段冒充当前完整代码。仅追加代码块之后的文字则保留反馈。
- 错误反馈保留并允许重试。独立桌面报告复制仍有独立状态实现，本轮没有把它误称为已全部统一。

## 待验证与后续优先级

1. 当前 Work 设置禁用浏览器访问，完整浏览器主题/窄屏/键盘矩阵仍待完成；不绕过访问限制。真实外部 OAuth 与付费模型调用也尚未验收，协议 fixture 仅验证集成行为。
2. 先补密集流与长 Markdown 的渲染基线，再决定是否合并同一绘制帧的 DOM 更新。消息存档与停止语义必须保持即时。
3. 系统凭据库、模型工具调用及真实有副作用的工具，应各自设计授权、超时、重试/幂等和故障恢复，不能通过界面优化宣称已实现。
4. 浏览器预览与正式桌面的能力差异、剩余独立报告反馈、设置禁用预览入口，继续按真实路径逐个统一；不为追求视觉完整启用空壳功能。
5. 报告追问需显式选择发送范围和用户动作；随包运行时及安装分发另做验收。本轮不扩大项目文件或报告向模型发送的范围。

本轮具体命令、计数、截图与交付门禁记录另见 `ui-detail-delivery-20261022.md`。没有新增依赖、环境变量、服务或发布操作。
