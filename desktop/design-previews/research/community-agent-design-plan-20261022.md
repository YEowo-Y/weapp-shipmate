# 社区调研 → 项目差异化交互：实施计划

用户明确授权调研、评审与实现。调研阶段只读，落地阶段采用既有前端工程流程，不以研究 skill 的默认只读模式阻断已授权实现。

## 核验与选型

论坛/社交内容用于发现问题，不自动当作规范。使用实际阅读的 GitHub issue/discussion、Hacker News、Reddit 一手讨论，交叉核对 W3C 和官方实现。记录发布日期、提案/已实现状态、可适用范围。当前 Vanilla TS / Vite / Tauri + Web Awesome + Lucide 足以实现，不加依赖，不引入通用生成 UI 协议。

## 本轮差异化切片

把真实的拒因查询结果转为「处理重点 + 依据核对」工作台，而非新增通用聊天壳：

- 在已校验匹配结果上提供 全部 / 需处理 / 需本人确认 / 缺少官方来源 四个查看重点及准确数量。
- `severity === blocker`、`manual_required`、缺少 `official_url` 分别决定分类；不解析自然语言，不把 requires 当材料字段，不推断规则适用或合规通过。
- 只切换当前结果可见条目，不重新查询或调用模型。隐藏无匹配分组；零项显示具体说明和查看全部入口。焦点留在选中按钮，来源展开状态保留；新查询/输入修改使旧结果失效。
- 完整复制/下载/加入会话继续使用完整校验结果，提示筛选仅影响显示，不能把部分清单冒充完整结果。
- 浏览器和正式桌面共用 explain.js / explain.css；使用已有原生可选结果按钮语义或已打包 Web Awesome 操作按钮，按上游可访问接口选择，不手写 tabs 行为或新组件框架。

## 验收与职责

实施代理仅拥有 explain.js、相关 explain UI tests/helper；父代理负责共享 CSS、native E2E、研究/创新评估、最终集成。代理互不覆盖文件。

先运行既有 explain 回归，新增分类交叉/零项/聚焦和来源保持/完整导出/输入失效测试并取得 RED→GREEN。运行全测试、lint、TS/Vite/Tauri 构建及 Windows WebView2 原生验收。现浏览器工具明确返回 Work 设置禁用，不绕过；保存阻塞和实际原生截图。视觉每轮以前轮真实 explain-result / explain-narrow 为基线并记录 verdict。

风险 high：共享结果展示和跨入口关键用户路径；不改服务端/权限/规则Schema/模型网络/存档格式。独立只读复核数据边界及无障碍。回退仅撤销本轮筛选、样式与测试，不重置脏工作区。正式发布不在授权范围。
