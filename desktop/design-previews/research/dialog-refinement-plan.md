# 对话框与对话区第二轮改造

2026-10-13。用户反馈：原生语义替换没有完成产品交互标准化。本轮沿用 redesign-existing-projects / frontend-ui-engineering，修改前对话、结果与组件合同测试 17/17 通过。

## 已确认的问题

- 工作方式选择和“更多”都使用同一 620px 阻断弹窗；轻量选择不应离开输入上下文。
- 确认、文件阅读、命令搜索没有尺寸/布局分型；关闭、遮罩、焦点、重复打开行为不一致。
- 附件、引用、斜杠菜单分别维护；存在同时打开和过滤后激活隐藏选项的问题。
- 输入区工具按钮、消息正文与弹层的视觉密度没有形成同一套桌面产品语言。

## 实施顺序与边界

1. 读取 Codex 当前官方命令/模型选择文档与 Claude 官方模型/Artifacts/键盘文档；实际浏览公开界面与截图。区分官方事实、视觉观察、项目选择，不声称已操作不可访问的原生客户端。
2. 工作方式、更多、附件采用浏览器 Popover API 锚定触发器；方向键浏览、Enter/Space 激活、Escape 关闭、外部点击关闭。只有确认/命令搜索/长文件使用 dialog，明确各自尺寸、描述、初始焦点和滚动区。
3. 修复附件/补全互斥与隐藏选项激活；保持草稿、IME、发送/停止、审批生命周期。对重要行为先记录复现，再验证回归。
4. 精修共享输入与消息的字体、宽度、留白、工具栏；不将设置切换伪装成真实模型接入。不增加框架或并行消息协议。
5. 浏览器检查主工作台、完整聊天、验收页与独立命令页：明暗、320/768/1440、键盘、焦点、遮罩、重复打开、过滤补全、嵌套审批关闭。运行根测试和显式预览 lint，独立审查。

## 文件所有权

- 主代理：ui.js / ui.css、共享弹层 API、preview.js 快捷键、调研与交付记录。
- 对话实现代理：chat.js / chat-full.html / components/composer.js，补全与附件接入共享 API。
- 视觉实现代理：components/composer.css / message.css / conversation.css，已有组件的视觉打磨。
- 主代理处理 responsive.js/css 与模态集成；不修改正式 Tauri 或后端。
