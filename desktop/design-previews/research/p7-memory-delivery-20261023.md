# P7 第二段：显式项目记忆

2026-10-23。本段完成正式 Windows 桌面的显式记忆、受控引用与本机验收；不代表 P7 全阶段或发布门禁完成。

## 用户路径与实际行为

1. 保存并选中项目，从工作台或更多功能打开“项目记忆”。新增、编辑或删除条目，查看来源和更新时间。新条目默认不允许引用。
2. 要用于聊天，先开启条目的引用许可，再从输入框 `+` 选择项目记忆；可查看所选内容和移除。单纯保存或开启许可不会发送。
3. 每次发送和重新生成都向原生库重新解析 ID。编辑采用最新文本；停用、删除或跨项目引用会阻止请求并给出恢复提示。等待期间停止、切换会话或销毁界面不会继续发送。
4. 重启恢复 SQLite 中的条目，但不恢复本次引用选择。删除无法撤回已发送内容或清除已有聊天。聊天备份导入不会创建记忆或扩大权限。

记忆是用户资料，作为有来源的 `user` 参考内容进入请求，不是系统规则、合规结论或工具授权。每条名称最多 80 个 Unicode 字符，正文最多 4 KiB；每项目最多 20 条，正文合计 16 KiB。全部附加资料仍受 8 项 / 24 KiB 和请求整包上限约束。

## 调研与取舍

官方 [Claude memory 文档](https://support.claude.com/en/articles/11817273-use-claude-s-chat-search-and-memory-to-build-on-previous-context) 支持查看、修改和关闭记忆；其当前不同作用域可共享内容，不能据此推断严格隔离。船友选择项目隔离，避免不同小程序的背景和偏好串用。

[OpenClaw memory architecture](https://docs.openclaw.ai/concepts/memory-architecture) 区分来源、写入者和注入信任等级。本段采用明确来源与显式引用，不引入整套记忆引擎。本轮读取官方文档，没有重新测量登录后的竞品截图，也没有复制竞品源码。

## 启动与复现

从仓库根目录启动：`npm --prefix desktop run tauri -- dev`。沿用既有开发工具链，无新增环境变量；管理记忆不要求模型密钥。真实聊天仍需用户连接并选择模型。浏览器预览没有本段原生 SQLite 能力。

原生验收必须使用新标识、独立测试库与随包运行时。命令依次运行，上一条失败时不得继续：

```powershell
$taskId = 'com.weappshipmate.acceptance.p7memory.' + [DateTimeOffset]::UtcNow.ToUnixTimeMilliseconds()
$taskDir = Join-Path (Get-Location) '.omx/artifacts/p7-memory-recheck'
New-Item -ItemType Directory -Path $taskDir -Force | Out-Null
$taskConfig = Join-Path $taskDir 'tauri-acceptance.json'
@{ identifier = $taskId } | ConvertTo-Json | Set-Content -LiteralPath $taskConfig -Encoding utf8
npm --prefix desktop run tauri -- build --debug --no-bundle --config $taskConfig
node scripts/desktop-native-e2e.mjs --memory --isolated-runtime "--expected-identifier=$taskId"
npm --prefix desktop run tauri -- build --debug --no-bundle
```

## 剩余边界

- 本机 SQLite 未加密，常见秘密检测不是完整 DLP；不应保存 API 密钥或密码。项目导出包含记忆，会话备份不含；项目备份导入恢复尚未实现。
- 项目切换时未保存草稿仅保留当前进程；异常退出不保证恢复。没有自动提取、向量搜索、跨项目共享或云同步。
- 外部模型账号与推理质量、独立浏览器、读屏器、OS 文件选择器、干净 Windows 安装及远程 CI 本轮未验证。原生 WebView2 不能替代这些验收；没有绕过 Work 浏览器访问限制。
- Vite 仍提示 `chat-transport.js` 混合静态/动态导入，以及主 chunk 593.46 kB 超过 500 kB；保留在 P8，不修改阈值隐藏提示。
- P7 文件监听、通知、其余设置与规则在线保鲜继续按总体计划推进；P6 写入仍需真实需求及独立审批/恢复门禁。
