# 共享组件基础样式收敛计划

## 检查结论与范围

现有依赖已满足这轮需求：本地打包 Web Awesome 3.14、Lucide、Floating UI 与 Markdown 渲染，不新增库或升级。原生 dialog/details/input 保留平台语义。全局工作流与质量配置沿用 package manifests、CI、desktop README 和现有测试脚本。

本轮只解决两类已定位问题：三种业务弹窗重复维护表面样式，桌面模型设置的阴影/遮罩/标题密度与历史和通用弹窗不同；设置中的六个规则图标操作绕开现有 Web Awesome 按钮，缺少 44px 窄屏目标。

## 修改前保护与最小实施

1. 记录当前历史弹窗、设置规则操作和原生模型连接截图；运行已有弹窗、历史、设置和组件回归。纯样式/标记收敛以真实截图、键盘和计算样式验证，不为 CSS 字面值新增镜像测试。
2. 在现有共享 app.css 集中三类 dialog 的字体、边框、圆角、表面、遮罩、标题与轻量进入动效；删除 ui.css、session-workspace.css、desktop styles.css 的重复定义。各业务宽度、滚动容器与行为保持独立。
3. 将六个设置图标按钮迁移至已有 wa-button.ui-action-icon，保留可访问名称、Lucide 图标和明确不可用状态；保留附近尚未接入的说明，删除已无调用的 native-icon-action 样式。
4. Web Awesome 圆角映射继续使用现有产品圆角令牌。桌面中文字体覆盖有平台背景，本轮不凭猜测移除，也不增加另一个字体依赖。

## 验收与边界

- 风险 medium，共享弹窗 CSS 需跨入口验收。执行 npm test、npm run lint、桌面 TS/Vite/Tauri 构建、Windows 原生回归和独立代码审查。
- 浏览器检查通用业务弹窗与历史的浅深色、320/768/1024/1440 宽度、短窗口、关闭后焦点、空搜索恢复、键盘操作及 reduced motion；设置按钮检查读屏名称、44px 窄屏命中区及明确演示反馈。
- 实际 native 检查模型连接、历史、拒因和数据弹窗的布局、重试/错误恢复路径。既有自动化协议 fixture 不冒充真实外部账号验证。
- 不改模型、数据、认证、规则编辑能力或存储格式；本轮不承诺发布，回退只涉及样式和按钮标记。
