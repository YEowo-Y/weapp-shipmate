# 首页、上线进度与偏好设置的功能呈现

日期：2026-10-23。承接[功能呈现与阅读规范](functional-reading-design-20261023.md)，本轮落实到正式 Tauri 桌面入口，不将开发预览页面视为正式功能。

## 真实来源与取舍

| 本轮核验的来源 | 本项目采用的做法 | 不照搬的部分 |
| --- | --- | --- |
| [GOV.UK Task list](https://design-system.service.gov.uk/components/task-list/) | 简短任务名称、明确文字状态、长标题与状态窄屏换行 | 官方组件面向可自选顺序的任务；本项目阶段有前置条件，保留真实阶段顺序和下一步判定，不直接移植组件 |
| [GOV.UK Radios](https://design-system.service.gov.uk/components/radios/) | 用 fieldset、legend 和可点击标签组织单选，保留标准键盘行为 | 问卷避免预选的规则不适用于已有保存值的设置；主题和字号必须反映用户当前偏好 |
| [IBM Carbon Empty states](https://www.carbondesignsystem.com/building-blocks/core/patterns/empty-states) | 缺失项目和成果时解释原因并给出具体下一步；让主要动作有主次 | 不为没有数据的页面添加虚构进度、装饰插画或多个等权重主按钮 |

这些依据用于信息结构与行为选择，不冒充 Codex/Claude 的内部规范。此前规范中的 WCAG、USWDS 与社区长标题讨论继续适用；正式原生截图用于判断此次落地效果。未引入新的框架、字体、图标包或动画库，也未复制来源代码。

## 页面与用户路径

### 首页

呈现顺序为「当前项目 → 开始检查与准备 → 继续处理 → 偏好设置」。主入口是本地预检；无项目时聚焦目录选择，已有可用目录时聚焦执行按钮，导航本身不运行工具。上线清单与拒因查询作为并列的辅助任务，以一句说明解释用途。

当前项目名称与主体来自真实项目快照，名称按文本显示。最近报告复用独立阅读视图，缺失报告时保持明确空状态。上线进度、项目维护、显式记忆和模型连接保留各自真实入口，用同一图标、标题和说明结构展示。布局最多两列，在窄内容区回到一列。

### 上线进度

固定头部只放简短标题和关闭按钮，项目名称与范围说明进入可滚动正文，避免长名称和放大字体挤掉阅读区。随后显示实际阶段统计、下一步与项目事实入口。阶段数和状态来自 `deriveWorkflow`，不凭自然语言或人工勾选伪造官方通过率。编号与文字状态兼顾定位和可读性；展开后阅读要求、来源、备注和明确动作。

未提交事实和阶段备注在本次应用运行期间按项目保留；刷新记录或关闭重开不会隐式保存。已保存内容仍走现有原生校验和版本控制。草稿不是持久备份，应用退出后不恢复未提交内容。

草稿记录初始事实、规则或阶段记录的依据。刷新发现依据变化时，输入仍可读取复制，但不能使用新版本号静默覆盖；界面展示新保存事实，并提供明确的放弃草稿/旧备注动作。用户重新核对后再提交，不自动合并业务判断。

### 偏好设置

按「外观 → 通知 → 连接与项目数据」分组，顶部的节导航滚动到实际内容并移动键盘焦点。主题选项提供轻量 CSS 预览，仍使用原生单选和可见选中标记。字号示例直接展示当前偏好；保存反馈与恢复动作保留在页底，不靠临时 toast 表达失败。

现有系统通知控制器、模型连接、会话备份、项目管理、来源核验和项目维护继续共用既有功能；打开设置不启用通知、不发起模型或网络请求。重开设置从概览开始，关闭后回到可见入口。

## 组件与工程边界

- 继续使用锁定的 Web Awesome 3.14.0、已有 Lucide 图标、原生 dialog/details/fieldset 和共享主题 token；没有重复安装 React/shadcn。
- 首页专属样式进入 `home.css`，不再依赖预览首页样式；上线进度样式从通用样式表移到 `workflow.css`，减少跨页面覆盖。
- 正文跟随现有字号偏好，关键标题允许换行；状态有文字说明，键盘焦点可见，减少动效设置沿用现有实现。
- 不改变模型协议、权限、SQLite 表、工具执行或通知投递机制。新增内容均表达现有真实功能。

验收命令、实际数量、原生截图和未验证边界记录在本轮交付报告中；截图和几何检查不能证明整个产品符合 WCAG 或安装发行质量。
