# 主持人一页卡 · 五人首跑练习

准备日期：2026-10-25。仅为练习材料，尚无真实参与结果。先阅读[首跑说明](../14-first-run-and-trial.md)，再把[参与者卡](participant.md)和`practice-miniapp`目录交给参与者。本轮不要求模型密钥，不联系微信后台，不注册或提交审核。

## 开始前

- 为参与者分配P01–P05编号，使用对应的`records/Pxx.json`；取得同意后才改`consent_recorded`。姓名和联系信息不写入记录。
- 填写候选版本、SHA256、实际入口、OS/架构、WebView2和网络情况；不要发送尚不存在的下载链接。没有入口、系统拦截或参与者退出都如实记录。
- 参与者解压后复制一份练习目录到自己可写的位置。目录含静态教学信号，不是真实业务，也不是可提交审核的成品。
- 记录练习开始时间。说明可随时停止；截图须单独同意并去除用户名、绝对路径、账号和秘密。

## 只读任务，不提示按钮位置

1. “请打开工具，选择练习目录，运行一次预检。”记录选择目录、首次结果的耗时与求助。
2. “请读出一项发现：你认为接下来应改代码、去后台、准备材料，还是人工确认？依据是什么？”不暗示分类答案。扫描可能同时产生多类提示，记录实际规则ID及原话。
3. “请生成上线导航。对练习里没有说明的主体、支付、个人信息和域名事实，请保留不知道。你下一步会做什么？”观察未知是否被保留；报告有定位教学线索不等于参与者应声明真实业务使用定位。
4. “请打开拒因查询页面，先不输入文字。你认为现在是否已经有一次查询结果？”记录初始界面，不代填审核反馈，不把空白理解成已审核。
5. “请导出这个练习项目的项目备份，再从项目管理预览并追加恢复，重新绑定同一个练习目录。”明确选择**项目备份**，不是会话备份；不归档或删除原项目。观察导入历史标记、记忆默认关闭、权限/监听/通知/阶段状态未自动恢复。
6. “请关闭再打开，说明你看到的是本机新检查还是导入历史。”结束后由参与者决定是否保留练习数据；不要求删除真实项目。

主持人解释边界（在参与者独立作答后说明）：定位调用在`if (false)`分支中，不会真实执行。静态命中不等于运行违规；参与者说“删除不需要的示例”也是有效下一步。不要为测试修复而强迫其勾选业务需要定位，不把补充声明当成真实业务合规已完成。

## 记账和判定

各阶段用`pass/fail/blocked/not-run`；第一次求助及帮助内容单列。提供帮助后成功不能覆盖独立操作受阻。导航理解保留原话，按[五人计划](../11-outreach-plan.md)判断，原有≥3/5目标只评价独立理解。

导入恢复、安全告警、动作分类、未知保留、空拒因页各自记账，不合并成虚构“整体通过”。模型连接、源码修复、微信真实提交均不在本练习范围。受限app.json修复候选已通过本轮原生验收；本练习仍不要求使用它或确认虚构业务。普通项目导出不含修复日志、修复备份或源文件，不能作为修复恢复包。

请勿提前填预期答案为结果。五个空JSON仍为`not-run`，自动化及维护者自测不能计入五位真实用户。
