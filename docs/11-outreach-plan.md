## 找谁（5 人画像，按易触达排序）

1. 正在或曾经**独立上线过微信小程序**的个人开发者（最贴目标用户）
2. 写过小程序但**卡在过审/备案/类目**环节的开发者（痛点在体）
3. 会写代码但**从未碰过小程序生态**的 web 开发者（测导航对新手的可读性）
4. 用 uni-app / Taro 的跨端开发者（测框架覆盖的说服力）
5. 任何愿意花 10 分钟的技术朋友（对照组：完全无上下文能否读懂）

招募候选渠道：个人开发者社群或朋友直邀；本文件不触发对外联系。取得参与同意后使用P01–P05匿名编号，联系方式与结果分开保存，不在仓库记录姓名、账号、真实源码、密钥或用户绝对路径。

## 给什么（统一物料，分开统计）

- **A（材料理解）**：预先生成的导航输出和无敏感内容的报告样例，标为 `material-only`；只能测理解，不能证明安装或首跑成功。
- **B（主试用：桌面）**：同一版本、同一SHA256的Windows安装器，加上真实可达入口、签名状态和前置要求。按[首跑说明](14-first-run-and-trial.md)完成维护者验收后再交给参与者；目前没有现成公开安装器入口。
- **C（附加：MCPB或CLI）**：只给已有兼容宿主或开发环境的参与者，单独统计。MCPB不是独立桌面应用；旧GitHub rc.3命令需要仓库权限，不能作为面向普通用户的一键安装材料。

材料理解任务指令：**「读完后，用你自己的话说：你的下一步是做什么，依据是什么？」** 不解释、不引导。桌面主试用先让参与者从入口独立获取、安装和打开，再执行下方统一任务。

下载或安装失败者仍保留在五人计划中，不能只统计成功进入应用的人。缺席记“未执行”；替补使用新编号并保留旧记录。若首跑受阻，可记录阻塞后继续A材料理解，但不得覆盖主试用结果。

## P3 正式桌面试用脚本（2026-10-22准备，2026-10-25更新，尚未招募）

本轮只准备任务和记录格式；没有联系用户，没有真实试用结果，不计入上面的 3/5 门槛。使用者需同意参与，项目可选无敏感信息的练习目录，不要求输入模型密钥。

统一任务：打开一个项目，填写主体与实际业务；不确定的事实保留“尚未确定”。打开“上线进度”，不接受主持人解释，口述下一步的具体动作及判断依据。然后查看该阶段的官方来源，区分应用中的人工准备记录与官方实际完成状态。完成一项后人工确认，修改一项项目事实，再说明为什么出现“待重检”。最后执行两次相同文件范围的预检并比较报告，解释“未再检出”能证明什么、不能证明什么。

主持人只读任务，不指示按钮位置；分别记录获取、安装、首开和首次有效结果的耗时。遇阻时记录告警原文、所处界面、耗时和是否求助；记录首次帮助的时间和内容，“帮助后完成”不能覆盖“独立失败”。不要求关闭安全保护、移除下载标记、提供密钥或共享账号。

参与者认为不适用时，记录其原因，不替其完成事实字段。参与者可随时停止，录屏/截图另行征得同意。测试结束关闭再打开确认练习记录，允许参与者导出并决定保留；自愿卸载时记录正常卸载和可见遗留数据，不以卸载成功推断所有数据已删除。
